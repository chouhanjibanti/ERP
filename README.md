# EduPulse ERP frontend

The application runs as one Next.js project. The existing MongoDB models,
controllers, services, middleware, and route definitions now live in
`src/server/api`; the Next.js API route handler runs them without a separate
Express server process. Existing ERP screens and `/api/...` URLs remain
available, including authentication cookies, multipart uploads, and file
downloads.

## Run locally

Requirements: Node.js 20.9 or newer and MongoDB. The backend runs inside the
Next.js server; no separate Express process is needed.

1. Start MongoDB.
2. Copy `Frontend/.env.example` to `Frontend/.env.local` and set
   `JWT_SECRET` (at least 32 characters). `MONGODB_URI` defaults to
   `mongodb://localhost:27017/erp`; configure SMTP values only if password
   recovery email is required. `FRONTEND_URL` defaults to
   `http://localhost:3000`.
3. In `Frontend`, run `npm install` if needed, then `npm run dev`.
   Open `http://localhost:3000`.

## Seed test data

The test dataset is generated by `scripts/seed-database.cjs`; it creates five
valid documents for each non-admin Mongoose model (145 documents across 29
schemas). Admin accounts are provisioned separately.
Configure `MONGODB_URI` in `.env.local` or `.env`, then run:

```powershell
npm run seed:check
npm run seed
```

`seed:check` validates the fixture documents without changing MongoDB.
`seed` inserts or updates only its deterministic test fixture IDs and does not
delete other records. These fixtures are for development only; do not use them
with production data.

## Admin login accounts

The two initial admin accounts are:

| Email |
|---|
| `admin@schoolerp.com` |
| `superadmin@schoolerp.com` |

Passwords are never stored in this README. Set `ADMIN_ONE_PASSWORD` and
`ADMIN_TWO_PASSWORD` in `.env.local` (not `.env.example` or source control),
then run:

```powershell
npm run seed:admins
```

The provisioning script stores bcrypt password hashes in MongoDB, creates or
updates these two accounts, then removes all other documents from the admin
collection. `npm run seed` does not create test admin accounts. Public
registration pages have been removed; old registration URLs redirect to the
login portal.

For staff and student accounts, use existing database records or provision
them through a trusted administrative process.

## Production

Run `npm run build` followed by `npm start`, or build and run the frontend
container with `docker build -t edupulse-frontend .` and
`docker run -p 3000:3000 edupulse-frontend`.

Set the environment variables at runtime. The Next.js server must be able to
reach MongoDB and write uploaded files to `src/server/api/public`; mount that
directory as persistent storage when running in a container.

The legacy student-account router was not mounted by the old backend and has
overlapping paths with admission routes, so it remains in the migrated source
but is not mounted. Other mounted backend routers keep their previous route
contracts.
